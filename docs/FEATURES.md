# NapTable 功能说明

本文档记录面向使用者的功能行为。项目结构、平台兼容性、签名和测试命令见[开发与构建](DEVELOPMENT.md)；服务端运维与 API 见[服务端说明](../server/README.md)；实时活动协议见 [Live Activity v2](live-activity-v2.md)。

## 课表视图

顶栏提供日、周、月三种视图，共用学期选择、溢出菜单和课程编辑入口。

- 日视图和周视图使用按节次排列的课表网格，可以按天或按周翻页。
- 月视图使用日历布局，每格显示公历日、农历或节日，以及最多三个课程圆点；选中日期后，下方列出当天课程。
- 月视图中的「日视图」入口会跳到选中日期所在的教学周。
- 课程可以来自教务导入，也可以手动添加、编辑或保留为自定义课程。
- 学校不在列表里时，「其他学校 / 手动创建」会引导用户依次设置第一周的星期一和学期总周数、节次时间（可按上午/下午/晚上的起始时间、课时和课间快速生成），再逐门添加课程。每门课可以有多个上课时间，周次支持每周、单周、双周和逐周自选；时间冲突会提示但不拦截。学期、周数和节次保存在这张课表上，之后在「设置 › 我的课表」里修改。首次使用的引导里也有这个入口，这时至少要添加一门课才能完成引导。
- 没有固定星期和节次的自由时间课程会单独列出，不会强行放入课表网格。
- 课表支持生成图片分享和导出 ICS 日历文件。

## 农历、节日与调休

农历和节日由 `WidgetCore/ChineseCalendar.swift` 离线计算，App 与小组件共用同一套结果，并按公历年缓存。

- 支持常见农历节日、部分公历节日和法定假期提示。
- 月视图始终显示农历和节日；小组件可单独控制农历日期、节假日提示和最近节假日常驻显示。
- 法定假期按照固定规则计算，不包含国务院每年单独发布的调休和补班安排。
- 调休由服务端学期配置按日期覆盖：`off` 表示当天放假，`swap` 表示当天改上指定日期的课。
- 补班日显示被补日期的课程，放假日不显示课程；周视图和月视图会显示相应的「班」「休」标记。

## 小组件

小组件不直接访问网络。App 将当前课表编码为 payload 写入 App Group，扩展从共享存储读取并生成时间线。

- 提供临近课程、今日课表、两日课表等布局。
- 默认只展示当天课程；当天课程结束后，可以选择显示明天课程、保持「今天没有课程」，或显示最近节假日。
- 时间线会在课程开始和结束边界额外刷新，不必等待固定刷新周期。
- 小组件使用与 App、实时活动共享的主题和显示选项。
- 点击小组件会通过 `naptable://schedule` 回到 App。

## 实时活动与灵动岛

实时活动只展示当天的课程。课程进入设置的提前显示窗口后出现，下课时结束或切换到当天的下一节课。

- 提前显示时间可选 15 分钟、30 分钟或 1 小时，默认 1 小时。
- 开启「课间也保留」后，课间会继续显示并倒计时到今天的下一节课；当天没有后续课程时自动收起。
- 今天第一节课尚未进入提前显示窗口时，不会一早显示晚上的课程。
- App 被系统挂起时，后台任务会尝试在课程边界收起或切换实时活动；系统可能调整实际执行时刻。
- 打开「显示实时活动」后，App 把课表的节次、周次和提醒设置上传给服务端（不含课程名、教师和教室），由服务端算出每节课的提醒时间并通过 APNs 启动活动，不打开 App 也会一直提醒到学期结束。iOS 26 及以上还会在本机预约最近几节。iOS 17 只能预览效果。
- 课程文案由 App 根据本机课表生成；服务端的推送只标出这个活动的时间段。共享课表的课例外：推送里带着服务端上的分享内容，手机上的分享还没更新时也能显示对方的新课。
- 提示来源是共享课表时，实时活动会标出这张课表的名字；如果自己同一时间也在上课，灵动岛和锁屏会把两节课并排显示，各自倒计时；两边的连堂课都按本机「分节计时」设置决定是否分节、是否显示课间。
- 关心共享课表时两张课表合在一起提醒：自己的课和对方的课分别按各自的提前显示时间提醒（设置页多一个「对方课程提前显示」）；两边时间重叠的课合成一个实时活动：自己的课在上时自己的课占主位、对方的课并排，否则对方的课在上；都没在上课时倒计时到最近的下一节。不重叠的课各自单独提醒。合并活动已经在显示时，后加入的课到了它的提前显示时间会再响一次「课程提醒」。一串相互重叠的课超过 8 小时时，在显示变化的时刻交给下一个实时活动。
- 分享者更新或撤销分享后，服务端会直接替关心的人重新安排，不需要对方打开 App。
- 走学校作息的课表由学校的公共上下课广播刷新画面；关心共享课表或作息与学校不一致时，每个实时活动由服务端在显示变化的时刻单独推送刷新。

## 从教务导入

导入的课程在写入课表之前会先检查时间冲突：同一天、节次相交、并且确实有共同周次的两行才算撞车（单双周轮流上的课节次虽然重合，但不会被误报）。

- 撞在一起的课按「组」呈现，A 撞 B、B 撞 C 时三节会放在同一组，需要选出保留哪一节；冲突没处理完不能导入。
- 没选中的课不会被丢掉，只是收起来：课表、小组件、实时活动和分享里都看不到它，但记录还在。
- 两节课的周次只是部分重叠时会再问一句：整节收起来，还是只收起重叠的那几周、其余周次照常上课。选后者时这节课会拆成「照常上课」和「收起来」两段。
- 收起来的课在「设置 → 课表 → 收起的课程」里可以随时恢复或删除；恢复后它会回到原来的时段，和当初保留的那节并排显示。

## 学校配置与课表分享

NapTable 服务端可以集中保存学校的学期开始日期、总周数、节次时间和调休表。App 导入课表时按学校和学期匹配配置，并缓存配置供离线使用。

分享内容是「课程 + 发布时的学校学期时间配置」的快照，包含节次时间、第一周周一、总周数和调休。因此读取他人分享时，不需要本机配置对方学校，也不会错误套用自己的作息。

- 分享码用于读取，写入和撤销使用创建分享时返回的一次性 `writeToken`。
- 分享者可以在 App 中同步当前学校的校历时间；管理员之后修正配置不会悄悄改变已发布的分享。
- 可以把分享课表设为小组件和实时活动的提示来源；它不会替换 App 主界面的课表。
- 内置 NJU 配置仅用于演示和校准，使用前应按实际校历与作息核对。

详细的服务端启动、管理员网页、API、APNs 密钥和安全边界见 [`server/README.md`](../server/README.md)。
