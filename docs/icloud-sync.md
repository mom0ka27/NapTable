# iCloud 课表同步

在「设置 → iCloud 同步」开启；默认关闭。同一 Apple 账号的各设备分别开启。新设备可以在首次引导选择「从 iCloud 同步已有课表」，确认接收后点「完成」进入课表。同步自己的课表（含隐藏课程）、学期/节次/季节作息/调休设置、已保存的共享课表及备注、分享管理凭证和关心对象。跨账号分享继续使用原有分享码服务。

实时活动开关、自己和共享课程的提前显示时间、分节计时、系统权限、实时活动隐私许可、推送令牌、实时活动预约、通知权益、当前选中的课表、显示偏好与背景图片均由本机保存，不参与同步。旧版同步文档里的通知偏好仅用于兼容解码，合并和写入前会移除，既不上传也不应用到本机。统一假期缓存由设备向业务服务器获取。管理凭证存放在用户的 CloudKit 私有数据库，通过同步拿到凭证的设备可以管理既有分享。

App 不单独保存学校账号和密码，也不把它们纳入同步。导入网页仍使用持久会话，Cookie、网页缓存和登录状态保留在本机。

## 检查与确认

本机新增、编辑和删除课表自动上传。关心对象、共享备注、管理凭证，以及只涉及课表名称、学期、节次等配置的变化自动同步，不弹提示。

只有云端新增、删除或课程内容变化（含共享课表的课程变化或撤销）需要确认。确认页只列远程课表更新、修改时间和修改设备，不显示本机上传项或独立设置变化。同一内容的时间戳、设备名称或记录版本变化不会触发提示。旧数据没有设备名称时显示设备标识前缀，不推测其名称。

用户可以「暂不接收」，待确认清单保留，轮询不会重复弹出，之后从设置继续。等待期间，本机修改上传和独立设置同步继续进行，云端待确认课程仍保留、本机课程不被替换；关心对象依赖尚未接收的共享课表时，等待该课表确认后再应用。接收自己的课表时逐张选择：

- **更新对应课表**：已有同一 UUID 的课表采用云端版本。
- **替换当前课表**：覆盖当前课表内容，保留当前本机数字 ID，并加入云端课表的同步身份；原当前课表 UUID 写入删除标记，相关分享管理记录改绑到云端 UUID。这个合并结果也会同步给其他设备。
- **新建课表**：保留本机版本。若本机已有对应课表，则云端内容生成新 UUID，保留两份；首次接收没有对应课表时使用云端原 UUID。

一次只能将一张云端课表替换到当前课表。当前课表本身有另一项待接收的修改时，不能同时成为其他课表的替换目标。远程删除和共享课表的课程变化也列在确认清单中。

确认前重新检查账号、本机文档和云端版本。待确认的课程或替换目标的课程发生变化时重新确认；无关设置变化自动处理，不重置选择或重新弹出。上传期间本机有新编辑时保留本机内容并重试上传；同时出现新的远程课程变化时才重新生成确认清单。

## Apple 开发者配置

代码已经声明 `iCloud.com.niyiwei.naptable` 容器与 CloudKit entitlement。发布前仍需在 Apple Developer / Xcode 中完成以下操作（本地代码无法代替开发者后台配置）：

1. 为 `com.niyiwei.naptable` 启用 iCloud / CloudKit，将容器 `iCloud.com.niyiwei.naptable` 关联到该 App ID；所有平台使用同一个容器。
2. 更新签名描述文件。在登录测试 iCloud 账号的签名开发构建上开启同步并上传本机课表，创建 Development schema：记录类型 `ScheduleLibrary`，字段 `payload`（Asset）。也可在控制台手动建表。记录 `schedule-library-v1` 在用户的 private database 默认 zone 中。无需 public 权限或查询索引。
3. 在 CloudKit Console 将 schema 部署到 Production，再验证 TestFlight / 发布构建。开发环境与生产环境数据隔离。
4. 在两台真机上验证首次合并、修改、删除、共享备注、分享更新与撤销；确认网络断开后修改保留，重连并打开 App 后同步；验证退出 iCloud / 切换账号时暂停。

本版在前台启动、内容修改后约 1 秒以及前台每 60 秒同步，可手动「立即同步」；未接入 CloudKit 静默推送或即时网络恢复监听，不保证 App 关闭后的即时同步。同步不会代替本机通知权限和实时活动隐私许可。

## 数据与冲突

- 本地课表使用持久 UUID；数字 table/course ID 在导入另一设备时重新分配。手动恢复备份产生新的 UUID，避免覆盖原课表。
- 同步文档按课表、已保存的共享课表、管理凭证分别记录修改时间与删除标记。首次同步合并不同实体，不使用“整机备份覆盖”策略。删除标记保留，防止离线设备重新带回旧数据。
- 同一实体的并发修改按修改时间选择较新者，相同时间按写入设备 ID 确定顺序。课表是合并单位，**不进行同一课表内课程字段的并发合并**；远程版本带来课程变化时可选择新建课表保留两份。收到并应用未来时间戳后，后续本机修改使用更晚时间。
- 已移除「恢复同步前的课表」入口及同步恢复副本生成逻辑。接收前可以选择新建课表。
- 新设备的空关心对象不会覆盖云端已有设置。删除或撤销共享课表时自动清除指向它的关心对象。实时活动偏好不会进入本机同步日志或云端文档。
- 文档格式升级为版本 2，可读取版本 1；修改设备名称是可选字段。参与同步的设备应更新到支持版本 2 的 App。CloudKit schema 仍只有一个 Asset 字段。
- 云端使用 CKAsset 保存整个文档（客户端限制 25 MiB），没有变化不上传，通过 `ifServerRecordUnchanged` 条件写入。并发写入最多尝试 3 次，读取到新的课程内容时重新确认，独立设置继续自动同步。本机保存失败时停止上传。
- 同步日志与课表写入同一个原子 JSON 存档，旧版存档缺少新增可选字段仍可读取。共享缓存沿用 UserDefaults，下一次保存会捕获与同步日志之间的差异。
- 关闭开关保留云端数据。保持同步开启并删除内容可传播删除；删除标记不包含课程或凭证正文。设备绑定首次成功识别的 iCloud 用户，账号变化会停用同步，避免将旧账号的数据自动上传到新账号。切回原账号后可重新开启。

## 验证

`bash tests/check-icloud-sync.sh` 使用内存传输层覆盖迁移、首次合并、同名课表收敛、ID/课程分组映射、隐藏课程、本机上传和设置不提示、远程课程确认、新建/替换课表、共享备注与管理凭证、关心对象自动同步、实时活动设置不上传且不受旧云端设置影响、延期确认期间的独立同步、条件写冲突、上传期间编辑、账号隔离及保存失败。`bash tests/check-sharing.sh`、`bash tests/check-share-rotation.sh` 和 `bash tests/check-live-activity.sh` 检查原分享和通知行为。

模型检查和未签名构建不验证真实 iCloud 权限、schema、配额或跨真机通信，发布前必须完成上述真机验收。

实现依据：[Apple CloudKit 条件写入策略](https://developer.apple.com/documentation/cloudkit/ckmodifyrecordsoperation/savepolicy)、[批量保存结果](https://developer.apple.com/documentation/cloudkit/ckdatabase/modifyrecords(saving:deleting:savepolicy:atomically:))。
